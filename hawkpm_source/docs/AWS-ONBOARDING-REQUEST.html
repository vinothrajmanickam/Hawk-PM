Each pipeline must set three CodeBuild environment variables (see Section 5). Please advise supported source types (CodeCommit, GitHub via CodeStar connection, Bitbucket).

4. Access for the Application Team

To push code and manage releases, please provide one of the following (least privilege preferred):

  • Option A (preferred): Pipeline-driven deploys — repo access and pipeline triggers on push; the team does not touch AWS directly.
  • Option B: A scoped IAM role/user (via SSO/federation if available), granted per environment, limited to: s3:PutObject, s3:DeleteObject, s3:ListBucket on that environment's bucket, and cloudfront:CreateInvalidation on that environment's distribution. (Production access may be restricted to approvers only.)

With Option B, the team deploys manually using:

aws s3 sync ./dist s3://<env-bucket> --delete
aws cloudfront create-invalidation --distribution-id <dist-id> --paths "/*"

5. CI/CD Build & Per-Environment Variables

A buildspec.yml is already committed in the repository root. It supports both environments from a single file. Create two pipelines (UAT and Production); set these CodeBuild environment variables on each:

VariableUAT pipelineProduction pipeline
APP_ENVuatproduction
DEPLOY_BUCKETUAT S3 bucket nameProd S3 bucket name
CF_DISTRIBUTIONUAT CloudFront distribution IDProd CloudFront distribution ID

The committed buildspec.yml (for reference):

version: 0.2
phases:
  install:
    runtime-versions:
      nodejs: 20
    commands:
      - npm ci
  build:
    commands:
      - if [ "$APP_ENV" = "production" ]; then npm run build:prod; else npm run build:uat; fi
  post_build:
    commands:
      - aws s3 sync dist/ "s3://$DEPLOY_BUCKET" --delete --cache-control "public,max-age=31536000,immutable" --exclude "index.html"
      - aws s3 cp dist/index.html "s3://$DEPLOY_BUCKET/index.html" --cache-control "no-cache,no-store,must-revalidate"
      - aws cloudfront create-invalidation --distribution-id "$CF_DISTRIBUTION" --paths "/*"
artifacts:
  base-directory: dist
  files:
    - '**/*'
Caching note: hashed JS/CSS assets are long-cached (immutable); index.html is served no-cache so new releases appear immediately after each CloudFront invalidation.
